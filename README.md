# El Troso

> *The path your memories keep alive when you walk it.*

**El Troso** is an Android companion for elderly people with mild cognitive
impairment (MCI) and their families. It runs entirely on-device with
**Gemma 4 E2B** (multimodal) and **EmbeddingGemma 300M**, and is built around
one metaphor borrowed from Veneto dialect:

*El troso* — *the path*. A path is born when you walk it. It fades when no
one walks it any more. And, sometimes, the most beautiful walk is the one you
take with someone who knows the path better than you do.

This is a submission to the **Google – Kaggle Gemma 4 Hackathon** (May 2026).

---

## Why El Troso

When my grandfather Giorgio (86, Padova) starts forgetting the everyday names
and routes, his autobiographical memory — the one that holds *who he is* —
is paradoxically the strongest part of him left. Existing reminiscence-therapy
apps either need a clinician sitting next to him, or a network connection to
ship his life to a cloud he doesn't trust.

El Troso is the opposite: a private, offline, warmly written companion that
lets him *tell* a memory, *walk through it again later*, and *keep it alive*
through gentle games rooted in evidence-based memory care.

Three feelings drive every screen:

1. **A path is born when you walk it.** Telling a memory creates a footprint.
2. **A path fades when no one walks it.** Memories that aren't revisited grow
   pale on screen — a quiet visual signal, never a guilt-trip.
3. **The most beautiful walk is the one you take together.** Anyone in the
   family — child, grandchild, friend — can revisit a memory *with* Giorgio
   and leave their own footprint on it.

The whole product, including this README, is downstream of those three lines.

The seed corpus shipping with the demo is twelve real memories distilled from
Giorgio's autobiographical book *"Nonno parlaci di te"* (January 2025), with
his explicit consent. On first launch the app asks, opt-in, whether to load
them.

### A path in three acts

**Act 1 — The path is born.** Giorgio taps *Racconto* on the home screen.
He speaks for thirty seconds about his elementary school, holds up a black
and white photo from a tin box. The app transcribes on-device, files the
memory in his gallery as a fresh footprint, dark and clear. It now exists in
a place that is not his memory alone.

**Act 2 — The path fades. The path is walked again.** Two weeks later, the
hero card on the home suggests *"Today let's walk through your school days
again"* — that's the spaced retrieval engine kicking in (1 → 3 → 7 → 14 → 30
day curve, evidence-based). The school memory's footprint in the gallery
has grown pale, mirroring the science: memories not revisited fade. Giorgio
taps *Ripercorriamolo*, hears his own voice (the original recording), and
the footprint brightens again. The app silently logs *who* walked it, and
*when*. He can also play one of five evidence-based games against this
memory: a photo-matching deck, a single specific question generated by Gemma
("Who was the Economics teacher at Calvi?"), a free-recall guess from a
photo, or a *Continue the story* prompt where the app reads the first two
sentences and Giorgio narrates the rest, with Gemma giving warm, honest
feedback that never asks him to feel wrong.

**Act 3 — The path walked together.** His grandson, who lives in London,
opens the app on a visit. He selects *walker: grandchild* and revisits the
school memory. He doesn't know Italian very well, so he taps *Translate* —
Gemma 4 produces the English version on-device in a few seconds, preserving
proper names. They walk through it together. Two footprints, side by side,
same path.

That is the product. Everything below is the engineering that holds it up.

### Five evidence-based games

Each game is grounded in published research on cognitive care for MCI / AD,
**personalized on the user's real memories** (not generic content), and
follows the *errorless learning* principle: never make the user feel wrong,
but also never confirm a fact that isn't in the original memory. The full
references with rationale are in the next section.

| Game                              | What it does                                                                                                                                |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **Today (G4)** — spaced retrieval | Suggests the most overdue memory each day on a 1-3-7-14-30 day curve                                                                        |
| **Photo memory (G1)**             | 4×3 photo-matching with the user's own pictures; each match registers a walk                                                                |
| **Recognize and tell (G3)**       | A memory's photo is shown; user describes it freely; Gemma 4 compares against the *text* of the memory and gives warm but honest feedback   |
| **Guess together (G2)**           | Gemma generates one specific question about a memory (year / place / person); user answers; Gemma evaluates against the memory's text       |
| **Continue the story (G5)**       | App reads the first 1–2 sentences of a memory; user continues out loud; Gemma compares with the true continuation and gives warm feedback   |

A built-in `GameInfoSheet` (ⓘ icon in every game's app bar) explains, for the
user themselves, *what* the game is, *why* it works, and lists the *sources*
as tappable DOI / PubMed links — opened in the system browser, not in-app.
Citation transparency lives inside the product, not only in this README.

## Evidence-based design

The five games and the spaced-retrieval engine are not opinion. Each rests on
a specific paper from the cognitive-care literature. We list them here with
*what each paper is*, *why we chose it*, and *which feature it informs* —
because a project whose distinctive claim is *EBM-grounded design* should not
make the reader chase the references on their own.

| Reference | What it is | Why we chose it | Feature |
|---|---|---|---|
| [Woods B et al., Cochrane CD001120 (2018)](https://doi.org/10.1002/14651858.CD001120.pub3) | Cochrane systematic review of 22 RCTs (n > 1800) on reminiscence therapy in dementia. Conclusion: small but consistent benefits on cognition, mood, and quality of life; **the 1:1 facilitator + personalized stimulus** protocol shows the largest effect. | This is the strongest evidence base for the *whole concept of El Troso*. We replace the human facilitator with on-device AI and the photo album with the user's own gallery. | G3, F10, the entire reminiscence loop |
| [Cotelli M et al. (2012), PMID 22466023](https://pubmed.ncbi.nlm.nih.gov/22466023/) | Controlled intervention study of guided narrative cognitive stimulation in mild Alzheimer's disease. Improvement on autobiographical episodic recall. | Validates *narrative continuation* as a cue for autobiographical memory — the exact mechanism G5 uses (read the incipit, ask the user to continue). | G5 |
| [Hopper T et al. (2013), PMID 23886395](https://pubmed.ncbi.nlm.nih.gov/23886395/) | Systematic review of spaced retrieval training (SRT) interventions across the dementia spectrum. Maps the canonical paradigm "stimulus → question → answer → corrective feedback at expanding intervals." | We follow this paradigm one-for-one in G4 (Today) with the 1-3-7-14-30 day curve, and in G2 (Guess together) for the question-answer-feedback loop. | G4, G2 |
| USMART RCT (2017) — *Alzheimer's Research & Therapy* 9:26 | First RCT of tablet-delivered SRT in MCI patients. Statistically significant improvements on Word List Recall vs usual care. | Direct evidence that SRT *delivered through a touchscreen* works in this population — the technical premise of El Troso. G2 is essentially USMART's flow with the addition of personalized memories and on-device LLM. | G2, G4 |
| [Roediger HL & Karpicke JD (2006), DOI 10.1111/j.1745-6916.2006.00012.x](https://doi.org/10.1111/j.1745-6916.2006.00012.x) | The seminal "Power of Testing Memory" paper establishing the *testing effect* — active recall consolidates memory more than passive re-reading. | Justifies why we have *active* games (G2, G3, G5) on top of *passive* re-listening (F10 Ripercorri). The two are complementary, not redundant. | G2, G3, G5 |
| [Clare L et al. (errorless learning review), PMC3381647](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC3381647/) | Review of errorless learning in cognitive rehabilitation for early-stage dementia. Principle: feedback should never highlight the error; instead model the correct response without making the patient feel wrong. | Drives the entire prompt design across G2 / G3 / G5 — the model is instructed to redirect with modal phrases ("In realtà…", "A pensarci bene…") rather than "no" / "wrong" / "you don't remember." Crucially: errorless ≠ sycophantic. The prompts also forbid confirming facts that are not in the memory. | All three Gemma-mediated games |
| [Carstensen LL & Reed AE (2012), PMC3459016](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC3459016/) | Socioemotional selectivity theory and the *positivity effect*: in older adults, emotionally meaningful stimuli are processed and remembered preferentially. | Explains why we insist on *autobiographical* photos and texts as game material instead of generic pictograms — the personalization is not a UX nicety, it is the engagement mechanism. | G1, G3, G4, G5 |
| [SenseCam corpus follow-up (2014), PMID 24528204](https://pubmed.ncbi.nlm.nih.gov/24528204/) | Study showing that review of autobiographical *images* increases retained detail at 2 weeks compared with written diary review. Visual cues outperform text cues for autobiographical memory. | Justifies that every game with a photo (G1, G3) prioritizes the image as the primary cue, with text as support. | G1, G3, F3 gallery |
| [Bluck S & Levine LJ (1998), *Memory* journal](https://doi.org/10.1080/096582198388478) | Theoretical paper: "Reminiscence as autobiographical memory: a catalyst for reminiscence theory development." Argues that *narrative continuation from a cue* is the most ecologically valid mechanism to stimulate autobiographical memory in domestic settings. | Clinically valid setups require a clinician. Bluck & Levine give the theoretical license to do reminiscence in the kitchen, with a tablet, mediated by an AI. That is what G5 is. | G5 |
| [JMIR Serious Games meta-analysis (2024), PMID 39083796](https://pubmed.ncbi.nlm.nih.gov/39083796/) | Meta-analysis of 14 RCTs (n = 714, 2017–2023) on digital serious games in AD and MCI. Conclusion: digital serious games outperform traditional training modalities on global cognition, daily behavior, and depression. | Validates the *paradigm itself* — that a phone-based game is a legitimate intervention vehicle in this population. Without this paper the games would be a stylistic choice; with it they are an evidence-aligned design. | G1, the games framework as a whole |

A more granular per-feature mapping (including the secondary references we
read but did not lean on) is in
[`docs/El Troso - Mappatura feature-evidenza.md`](docs/El%20Troso%20-%20Mappatura%20feature-evidenza.md).

> **Honesty note.** None of the *specific* games in El Troso has been the
> object of an RCT in this exact form. What we claim is *design integration
> of RCT-validated principles*, not *clinically validated intervention*. The
> distinction matters and is preserved verbatim in the in-app citations.

## Multilingual on-device

- **UI in Italian and English** with auto-detection from device locale, plus
  an explicit `IT · EN` picker in the drawer and at the top of the onboarding
  carousel. The choice is persisted across launches.
- **Memories carry their own language**: a new `Memory.originalLang` field is
  set at record time. Speech-to-text and text-to-speech follow the active UI
  locale, but **playback of a memory is always in the language it was told
  in** — an Italian memory read by a US TTS voice would be tragic.
- **Translate on demand**: when the user reads a memory in a UI language
  different from the memory's original language, a `Translate` button
  appears under the text. A tap calls Gemma 4 E2B with a dedicated
  translation prompt that preserves proper names (Pippo, Calvi, Mazzi,
  Teolo) and the warm first-person voice. Translations are *not* persisted —
  the demo runs entirely offline and stateless on translation.

## Privacy and on-device guarantee

- All inference, embedding and storage happen on the phone.
- The seed corpus (12 memories from Giorgio's book) is published with the
  explicit written consent of its author.
- Translations performed at runtime stay in RAM during the session and are
  not written to disk.
- The user can wipe everything from the drawer ("Restart the path").
- The "fully offline" claim is verifiable: with the device in airplane mode,
  every feature continues to work. `adb shell` network monitoring during a
  full session shows zero outbound traffic.

```
                       │
            ┌──────────┼──────────────────────┐
            │          │                      │
   GemmaService   VectorStoreService   STT/TTS Services
   (flutter_gemma)  (EmbeddingGemma +   (speech_to_text /
            │       SQLite vec store)   flutter_tts)
            │          │
            ▼          ▼
   ┌──────────────────────────────────┐
   │  Three model files on device     │
   │  ──────────────────────────────  │
   │  gemma-4-E2B-it.litertlm  2.4 GB │  multimodal: text + image + audio
   │  embeddinggemma-300M.tflite 171M │  RAG retrieval (seq 512)
   │  sentencepiece.model       4.4M  │  embedder tokenizer
   └──────────────────────────────────┘
```

- **Flutter SDK** ^3.11.5, target Android (Pixel 7a development device).
- **flutter_gemma 0.13.5** — Gemma 4 E2B installed as `.litertlm`,
  `PreferredBackend.gpu`, multimodal flags on (`supportImage`, `supportAudio`),
  `maxTokens: 2048`.
- **EmbeddingGemma 300M** with mixed-precision TFLite for on-device retrieval,
  similarity threshold tuned at 0.30 for short biographical queries.
- **No network usage during normal operation.**

## What we know we still don't know

This section is here on purpose. A project whose ethical posture rests on
*errorless learning ≠ accommodating dishonesty* should not pretend the
shipping build has no rough edges. None of these are excuses; each is a
conscious tradeoff or a real platform constraint.

### Translation quality on regional dialect

Gemma 4 E2B is a generalist multilingual model. Proper names (Pippo, Calvi,
Mazzi, Teolo) are handled well in our internal tests — they are preserved
verbatim. Heavily dialectal Veneto expressions ("ostia veci", regional
idioms) sometimes flatten in translation. We treat this as best-effort and
keep the original Italian visible alongside any translation; we never
*replace* the source. If quality on dialect proves insufficient under wider
testing, the right answer is a specialized translator, not the generalist
LLM — that path is in our v1.x backlog, not pretended-shipped today.

### Speech-to-text on Veneto-accented Italian

The on-device STT we use is the Android system speech recognizer, which
varies in quality by ROM version. On Pixel 7a it's solid for standard
Italian; on heavily accented speech it can drop syllables. A rule-based
post-processor for the Veneto vocabulary is mapped out in `MULTILINGUA_PLAN.md`
and queued for v1.x.

### One primary test user

The design has been built and validated in tight iterations with Giorgio
himself — every prompt change, every screen, every metaphor has been
re-tested with the person it is for. That is a strong signal of *fit* but
a weak signal of *generalizability*. Broader usability sessions with other
elderly users with MCI are the first item in the post-Kaggle plan, not the
last.

### iOS port — the honest reason

iOS is deferred, and not for lack of will. Two real platform constraints:

1. **The Swift LiteRT-LM API is currently text-only on iOS.** El Troso
   relies on Gemma 4 E2B's *multimodal* capabilities (image input for the
   photo-grounded games, audio input for transcription) — features that
   are part of the Android `flutter_gemma` plugin today but have no
   first-party iOS multimodal counterpart at the time of writing. A
   text-only iOS port would have to drop G3 *Recognize and tell*, which is
   the most-cited reminiscence-therapy game in our evidence map.

2. **iOS handles large model files differently from Android.** On Android
   we use `getExternalStorageDirectory()` and ask the developer to
   `adb push` three files (2.6 GB total). On iOS there is no equivalent
   user-facing path: large models must either ship inside the app bundle
   (App Store binary size review and download time become a real concern
   at this scale), be downloaded over the network on first launch (which
   would break our offline-only claim), or be sideloaded through the Files
   app (poor UX, unclear path). The right pattern for shipping multi-GB
   on-device models on iOS is still industry-unsettled.

Flutter is the strategic bet that absorbs both: when the LiteRT-LM Swift
API gains multimodal parity and the on-device model distribution story
converges, the same codebase ports without rewriting the UI layer. We
expect to revisit this in Q3 2026.

## Build it yourself

### Prerequisites

- macOS or Linux dev box with Android Studio and Flutter ^3.11.5
- Pixel 7a or any Android 14+ device with at least 6 GB RAM and a
  Tensor G3+ class GPU (development and testing have been done on
  Pixel 7a — your mileage may vary on older silicon)
- USB cable and ADB enabled

### Clone and configure

```bash
git clone https://github.com/<your-fork>/el_troso.git
cd el_troso/el_troso
flutter pub get
```

### Push the three model files

The model files are not bundled in the APK because of size and licensing.
Download them from the Gemma model card and push them to the device's
external storage:

```bash
adb push gemma-4-E2B-it.litertlm \
    /sdcard/Android/data/it.guidomarangoni.el_troso/files/
adb push embeddinggemma-300M_seq512_mixed-precision.tflite \
    /sdcard/Android/data/it.guidomarangoni.el_troso/files/
adb push sentencepiece.model \
    /sdcard/Android/data/it.guidomarangoni.el_troso/files/
```

> Note: on modern Android `pm clear` wipes external app storage too — you'll
> need to re-push if you ever clear the app data.

### Build and install

```bash
flutter build apk --debug
adb install -r build/app/outputs/flutter-apk/app-debug.apk
adb shell monkey -p it.guidomarangoni.el_troso \
    -c android.intent.category.LAUNCHER 1
```

The first launch shows the carousel; tap *I'm ready* to set up your profile.
On the seed-offer screen, tap *Yes* if you want Giorgio's 12 memories
pre-loaded for the demo experience.
